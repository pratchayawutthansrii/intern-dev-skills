## ตัวนี้เหมาะกับงานอะไร / ใครควรใช้?

- **ทีมพัฒนา Software และน้องฝึกงานใกล้จบฝึกงาน** ที่ต้องทำเอกสารสรุปโปรเจกต์, คู่มือส่งมอบงาน (Handover), หรืออัปเดต `README.md` ให้ตรงกับเวอร์ชันปัจจุบัน
- ลดปัญหาเวลาคนเก่าออกหรือสลับทีมแล้วคนใหม่เปิดโปรเจกต์ไม่ขึ้น ไม่รู้พอร์ตไหนรันอะไร หรือต้องตั้ง `.env` ตัวไหนบ้าง

---

## ตัวนี้ช่วยอะไรบ้าง?

1. **อิงจากโค้ดจริง ไม่เขียนน้ำท่วมทุ่ง** — ดึงพอร์ตจริง, คำสั่งจริงจาก `package.json`, และตัวแปรจริงจาก `.env.example` มาเขียน ไม่เดาคำสั่งที่รันไม่ได้
2. **มีผังระบบ (Mermaid Diagram) อ่านเข้าใจใน 10 วินาที** — วาดภาพเชื่อมโยง Frontend ↔ API ↔ MongoDB/TiDB ↔ Cloudflare ให้เห็นภาพรวมทั้งระบบทันที
3. **เชื่อม Pointer หาเอกสารล่าสุดเสมอ** — ถ้ามีเอกสารสรุปตามวันที่ (เช่น `README_2026-11-21.md`) จะอัปเดตลิงก์หน้าแรกให้คนเปิดเจอเวอร์ชันปัจจุบันทันที
4. **ปลอดภัย ไม่หลุดรหัสผ่านในเอกสาร** — แทนค่าลับทุกตัวด้วย Placeholder และตรวจทุก path/คำสั่งก่อนส่งงาน
